# 📚 জাভাতে অ্যাবস্ট্রাকশন (Abstraction in Java): সম্পূর্ণ বিস্তারিত নোট

---

## ১. অ্যাবস্ট্রাকশন কী? (What is Abstraction?)

* **মৌলিক ধারণা:** অবজেক্ট ওরিয়েন্টেড প্রোগ্রামিং (OOP)-এর ৪টি মূল স্তম্ভের (Encapsulation, Inheritance, Polymorphism, Abstraction) অন্যতম গুরুত্বপূর্ণ একটি স্তম্ভ হলো **Abstraction**।
* **সংজ্ঞা:** অভ্যন্তরীণ জটিল কাজ ও ইমপ্লিমেন্টেশনের খুঁটিনাটি গোপন রেখে ব্যবহারকারীর কাছে কেবল প্রয়োজনীয় কার্যকারিতা বা ফিচার তুলে ধরাকে অ্যাবস্ট্রাকশন বলে (*Hiding internal implementation details and showing only essential features*)।
* **বাস্তব জীবনের উদাহরণ (এসি ও রিমোট):**
* একটি এসি (AC) রিমোট দিয়ে তাপমাত্রা বাড়ানো-কমানো, মোড পরিবর্তন (Auto, Manual, Dry) বা ক্লিনিং কমান্ড দেওয়া যায়।
* ব্যবহারকারীকে এসির ভেতরের সার্কিট কীভাবে কাজ করছে বা ভেতরের তার কীভাবে জোড়া দেওয়া আছে তা জানতে হয় না। রিমোটের ইন্টারফেস ব্যবহার করেই পুরো এসি নিয়ন্ত্রণ করা যায়। এটিই বাস্তব জীবনের অ্যাবস্ট্রাকশন।

## ২. অ্যাবস্ট্রাক্ট মেথড (Abstract Method)

* **প্রয়োজনীয়তা:** কোনো সাধারণ বা জেনেরিক ক্লাসে (যেমন: `Animal`) এমন কোনো কাজ থাকতে পারে যার নির্দিষ্ট রূপ ওই পর্যায়ে নির্ধারণ করা সম্ভব নয় (যেমন: সব প্রাণীর ডাক বা `sayHello()` একরকম নয়)। সেখানে অর্থহীন কোনো বডি না দিয়ে মেথডটি কেবল ডিক্লেয়ার করে রাখা ভালো।
* **সংজ্ঞা:** যে মেথডের কোনো বডি বা ডেফিনেশন (`{}`) থাকে না, শুধুমাত্র মেথডের ডিক্লারেশন বা সিগনেচার থাকে এবং সেমিকোলন (`;`) দিয়ে শেষ হয়, তাকে **Abstract Method** বলে।
* **সিনট্যাক্স:** Access Modifier ও Return Type-এর মাঝখানে `abstract` কি-ওয়ার্ড লিখতে হয়।
```java
public abstract void sayHello();

```


* **কনক্রিট মেথড (Concrete Method):** যে মেথডের নিজস্ব সুনির্দিষ্ট বডি বা ইমপ্লিমেন্টেশন `{ ... }` থাকে, তাকে কনক্রিট মেথড বলা হয়।

## ৩. অ্যাবস্ট্রাক্ট ক্লাস (Abstract Class) ও এর নিয়মাবলী

* **ক্লাস ডিক্লারেশন:** কোনো ক্লাসে যদি কমপক্ষে একটিও অ্যাবস্ট্রাক্ট মেথড থাকে, তবে সেই ক্লাসটিকে অবশ্যই `abstract` ক্লাস হিসেবে ডিক্লেয়ার করতে হবে।
```java
public abstract class Animal {
    public abstract void sayHello(); // Abstract Method
}

```


* **মূল বৈশিষ্ট্যসমূহ:**
1. **Abstract ও Concrete মেথডের সহাবস্থান:** একটি অ্যাবস্ট্রাক্ট ক্লাসে অ্যাবস্ট্রাক্ট মেথডের পাশাপাশি সাধারণ কনক্রিট মেথডও থাকতে পারে (যেমন: সব প্রাণীর ক্ষেত্রে ঘুমানোর প্রক্রিয়া একই, তাই `sleep()` মেথডটিকে বডিসহ কনক্রিট রাখা যেতে পারে)।
2. **অ্যাবস্ট্রাক্ট মেথড ছাড়াও অ্যাবস্ট্রাক্ট ক্লাস:** কোনো ক্লাসে একটিও অ্যাবস্ট্রাক্ট মেথড না থাকলেও ক্লাসটিকে `abstract` ঘোষণা করা যায়।
3. **নরমাল ক্লাসে অ্যাবস্ট্রাক্ট মেথড নিষিদ্ধ:** কোনো সাধারণ (Non-abstract) ক্লাসের ভেতর অ্যাবস্ট্রাক্ট মেথড রাখা যায় না।
4. **ফিল্ডস এবং গেটার-সেটার:** সাধারণ ক্লাসের মতোই অ্যাবস্ট্রাক্ট ক্লাসে ভ্যারিয়েবল (যেমন: `name`, `age`) এবং তাদের Getter/Setter মেথড থাকতে পারে।

## ৪. সাবক্লাস ও ইমপ্লিমেন্টেশনের নিয়ম (Subclassing & Implementation)

যখন কোনো সাবক্লাস বা চাইল্ড ক্লাস (যেমন: `Dog` বা `Cat`) একটি অ্যাবস্ট্রাক্ট ক্লাসকে `extends` করে, তখন সাবক্লাসের সামনে ২টি বিকল্প থাকে:

1. **সবগুলো অ্যাবস্ট্রাক্ট মেথড ওভাররাইড ও ইমপ্লিমেন্ট করা:** প্যারেন্ট ক্লাসের প্রতিটি অ্যাবস্ট্রাক্ট মেথডের নিজস্ব বডি দিয়ে সেটিকে কনক্রিট করা।
```java
public class Dog extends Animal {
    @Override
    public void sayHello() {
        System.out.println("Woof");
    }
}

public class Cat extends Animal {
    @Override
    public void sayHello() {
        System.out.println("Meow");
    }
}

```


2. **সাবক্লাসকে নিজে Abstract ঘোষণা করা:** চাইল্ড ক্লাস যদি মেথডগুলোর বডি বা ইমপ্লিমেন্টেশন দিতে না চায়, তবে সেই চাইল্ড ক্লাসকেও `abstract` ঘোষণা করতে হবে।

## ৫. অবজেক্ট তৈরি ও পলিমরফিক রেফারেন্স (Object Creation & Polymorphic Reference)

* **সরাসরি অবজেক্ট তৈরি নিষিদ্ধ:**
* অ্যাবস্ট্রাক্ট ক্লাসের সরাসরি অবজেক্ট তৈরি করা যায় না (`new Animal()` লিখলে কম্পাইল এরর দেবে: *`Animal is abstract; cannot be instantiated`*)।
* **কারণ:** অ্যাবস্ট্রাক্ট ক্লাসে অসম্পূর্ণ মেথড থাকে, যার কোনো বাস্তবায়ন নেই। অবজেক্ট বানিয়ে মেথড কল করলে জাভা কী এক্সিকিউট করবে তা জানে না।


* **পলিমরফিক রেফারেন্স (Polymorphic Reference):**
* অবজেক্ট সরাসরি বানানো না গেলেও অ্যাবস্ট্রাক্ট ক্লাসকে **রেফারেন্স টাইপ** হিসেবে ব্যবহার করা যায় এবং চাইল্ড ক্লাসের অবজেক্ট দিয়ে তা ইনিশিয়ালাইজ করা যায়:


```java
Animal dog = new Dog(); // সম্পূর্ণ বৈধ
dog.sayHello();         // আউটপুট: Woof

```

## ৬. স্ট্যান্ডার্ড ও ব্লুপ্রিন্ট হিসেবে ব্যবহার (Vehicle Example)

* অ্যাবস্ট্রাকশন মূলত একটি চুক্তি বা স্ট্যান্ডার্ড হিসেবে কাজ করে।
* **উদাহরণ:** কোনো সংস্থা বা সরকার যানবাহনের জন্য একটি সাধারণ স্ট্যান্ডার্ড ঠিক করল যে প্রতিটি গাড়িতে অবশ্যই গতি বাড়ানো (`accelerate`) এবং গতি কমানো (`decelerate` / `brake`) ব্যবস্থা থাকতে হবে।
```java
public abstract class Vehicle {
    public abstract void accelerate();
    public abstract void decelerate();
}

```


* পরবর্তীতে `Car`, `Cycle`, `Bike` ইত্যাদি ক্লাসগুলো `Vehicle` ক্লাসকে এক্সটেন্ড করে নিজেদের নিয়ম অনুযায়ী সেই মেথডগুলোর বাস্তবায়ন করে।

## ৭. এক্সেস মডিফায়ার (Access Modifiers) ও অ্যাবস্ট্রাকশন

* **`private` নিষিদ্ধ:** কোনো অ্যাবস্ট্রাক্ট মেথডকে `private` করা যায় না। কারণ প্রাইভেট মেথড চাইল্ড ক্লাসে ইনহেরিট বা ওভাররাইড করা যায় না, যা অ্যাবস্ট্রাকশনের মূল উদ্দেশ্যের পরিপন্থী।
* **Default (Package-Private):** মেথডে কোনো মডিফায়ার না দিলে তা শুধু একই প্যাকেজের চাইল্ড ক্লাস থেকে ওভাররাইড করা যাবে। অন্য প্যাকেজের চাইল্ড ক্লাস তা দেখতে বা ওভাররাইড করতে পারবে না।
* **`protected`:** মেথডটিকে একই প্যাকেজে এবং অন্য প্যাকেজের যেকোনো চাইল্ড ক্লাস থেকে সহজে অ্যাক্সেস ও ওভাররাইড করার সুযোগ দেয়।

## ৮. অ্যাবস্ট্রাক্ট ক্লাসে কনস্ট্রাক্টর ও বেস্ট প্র্যাকটিস (Constructor & SonarLint Rule)

* **কনস্ট্রাক্টর তৈরি সম্ভব:** অ্যাবস্ট্রাক্ট ক্লাসের সরাসরি অবজেক্ট তৈরি না হলেও এতে কনস্ট্রাক্টর তৈরি করা যায়।
* **কনস্ট্রাক্টরের প্রয়োজনীয়তা:** চাইল্ড ক্লাসের অবজেক্ট তৈরির সময় প্যারেন্ট ক্লাসের নিজস্ব ফিল্ডগুলোর প্রাথমিক মান সেটআপ (Initial setup) করার জন্য এই কনস্ট্রাক্টর ব্যবহৃত হয় (চাইল্ড ক্লাস ভেতর থেকে `super()` দিয়ে প্যারেন্ট কনস্ট্রাক্টর কল করে)।
* **SonarLint কোড কোয়ালিটি রুল:**
* যেহেতু অ্যাবস্ট্রাক্ট ক্লাসের অবজেক্ট বাইরে থেকে সরাসরি `new` দিয়ে বানানো যায় না, তাই এর কনস্ট্রাক্টর `public` রাখার কোনো যৌক্তিকতা নেই।
* তাই অ্যাবস্ট্রাক্ট ক্লাসের কনস্ট্রাক্টরকে **`protected`** রাখাই স্ট্যান্ডার্ড কোডিং প্র্যাকটিস।

## ৯. প্রটেক্টেড ব্যবহারের আরেকটি উদাহরণ (Bank Account Example)

* ধরুন, `BankAccount` ক্লাসে `creditScore` ফিল্ড বা তার মেথড রয়েছে।
* আমরা চাই না যে এটি সবার জন্য `public` উন্মুক্ত থাকুক। আবার `private` রাখলে এর সাবক্লাস এটি পাবে না।
* তাই এটি `protected` রাখা হয়, যাতে শুধুমাত্র এর চাইল্ড ক্লাস (যেমন: `LoanAccount`) এটি অ্যাক্সেস ও ব্যবহার করতে পারে।

## 📌 সংক্ষেপে মূল পয়েন্টসমূহ (Quick Summary)

| বিষয় | বিবরণ |
| --- | --- |
| **Abstraction** | অপ্রয়োজনীয় জটিলতা লুকিয়ে শুধু প্রয়োজনীয় ফিচার প্রদর্শন করা। |
| **Abstract Method** | বডি ছাড়া মেথড ডিক্লারেশন, যা চাইল্ড ক্লাসে বাধ্যতামূলকভাবে ইমপ্লিমেন্ট করতে হয়। |
| **Abstract Class** | যে ক্লাসের অবজেক্ট সরাসরি তৈরি করা যায় না, তবে রেফারেন্স হিসেবে ব্যবহার করা যায়। |
| **Concrete Method** | স্বাভাবিক মেথড যার নির্দিষ্ট বডি বা কোড থাকে। |
| **Constructor** | অ্যাবস্ট্রাক্ট ক্লাসে থাকতে পারে এবং এটিকে `protected` রাখা বেস্ট প্র্যাকটিস। |
| **Private Keyword** | অ্যাবস্ট্রাক্ট মেথডে কখনো `private` ব্যবহার করা যায় না। |
